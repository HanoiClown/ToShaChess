# Публикация ToShaChess на GitHub

Для первой публикации используй **ToShaChess-GitHub**, подготовленную чистую папку. В ней нет сохранений, ключей, личного PGN-архива и истории коммитов старого частного проекта. Исходную папку `chess.com` целиком публиковать не нужно: её старая Git-история содержит личные отчёты.

1. Создай на GitHub пустой публичный репозиторий **ToShaChess**, без автоматически созданного README или лицензии.
2. В GitHub Desktop выбери File → Add local repository → папку `ToShaChess-GitHub`. Можно нажать Publish repository и снять Keep this code private, если репозиторий ещё не создан.
3. Для терминала: в подготовленной папке добавь remote и отправь ветку `main`:

```powershell
git remote add origin https://github.com/YOUR_USERNAME/ToShaChess.git
git push -u origin main
```

Заменить нужно только `YOUR_USERNAME`. В подготовленной папке уже есть первый локальный коммит. API-ключ в GitHub не требуется. После push workflow Windows проверит проект и соберёт приложение; результат появится в Actions → завершённый запуск → Artifacts. Workflow ещё не запускался на GitHub до публикации.

Для релиза создай tag `v1.3.1` и прикрепи проверенный ZIP приложения. Чистая сборка при первом запуске предлагает создать пользователя. При распространении исполняемого файла сохраняй включённые лицензии и соответствующие исходники приложения/Stockfish. Включи Private vulnerability reporting в настройках репозитория, если хочешь принимать закрытые отчёты.

Большая папка `library-packs` не входит в Git и основной ZIP приложения. Публикуй исходный загрузчик и [инструкцию](LIBRARY.md), чтобы пользователи получали данные напрямую из открытой базы Lichess. Сохранения `data` остаются личными: для публичного релиза используй `release/win-unpacked`, а не свою установленную папку с прогрессом.

Дальнейшую публичную разработку веди в папке/клоне ToShaChess-GitHub. `npm run prepare:github` — одноразовый экспорт из частного рабочего проекта; повторно экспортировать поверх существующего репозитория он откажется.
